    A command, made readable.

    Convert one literal docker run command into a draft Compose file. Supported flags are mapped explicitly; an unknown option stops conversion.

    No commands are executed. Quoting uses a limited POSIX-like syntax.

      Supported options and limits

      --name --hostname --user --workdir --restart --platform --entrypoint --network -p --publish -v --volume -e --env --env-file -l --label --cap-add --cap-drop --security-opt --dns --add-host --expose --privileged --read-only --init -i -t -it. Short attached forms such as -p8080:80 work.

      Detach and automatic removal flags are reported as runtime choices. Shell substitutions, variables, shell operators, compound commands and unknown flags are rejected. Named networks and advanced mount syntax need manual configuration. This is a conversion aid, not Docker validation.

      Know what the record means

      Structure first.
      Context matters.

      What gets compared

      Mapping order, whitespace and comments do not create differences. YAML anchors and merge keys are resolved within each document. Environment and label lists can be compared by key against their mapping form. Other arrays retain their order, including ports and volumes.

      Short and long port/mount syntaxes are not treated as equivalent. Paths use JSON Pointer notation; array positions start at zero. Added or removed mappings appear as one change with their full contents available.

      What stays outside

      No containers are contacted or started. Variables are not interpolated, referenced files are not opened, and separate override files are not merged. To compare effective configurations, run docker compose config yourself for each setup and compare those outputs.

      This is not a Compose schema validator or a prediction of deployment behaviour. YAML 1.2 core values are supported; custom tags such as !reset and !override are rejected.

      Your configuration stays here

      Pasted documents and local files remain in this browser tab. There is no automatic storage. Values are hidden by default in results and exported reports; revealing them affects both. Names and paths remain visible. Downloaded full-value reports and generated YAML may contain credentials.

      Parsing runs in a worker with size and time limits. A failed comparison leaves the earlier result visible and labelled; exports require a current successful comparison.
